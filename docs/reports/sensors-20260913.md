# SM-T630 sensor bring-up — 2026-09-13

## Result

The Galaxy Tab Active4 Pro's Qualcomm SSC sensors are available to Ubuntu
through `net.hadess.SensorProxy`. Live tests passed for the accelerometer,
ambient-light sensor, proximity sensor, magnetometer and derived compass
heading. GNOME is configured to allow display rotation, and automatic ambient
brightness is working through GNOME's ordinary power-settings daemon.

This establishes sensor discovery and measurement. Clean boot is now verified.
Physical rotation and suspend/resume survival are still required before the
integration is considered complete.

## Device-specific work

Samsung's 5.4 kernel exposes `/dev/adsprpc-smd-secure` with the downstream
FastRPC ABI. The packaged `hexagonrpcd` adds the legacy GETINFO, sensor-domain
attach, invoke and mmap layouts needed by that ABI. `iio-sensor-proxy` also
watches the downstream `fastrpc` subsystem so it can bind the SSC drivers.

Only the read-only sensor configuration and DSP runtime files from the exact
DZE3 stock image are used. Generated SSC registry state lives under
`/usr/local/share/t630/sensor-hexagonfs`; the Android persist partition is not
modified. The SM-T630 uses the upstream `ambient_light` sensor endpoint, not
the S9 Ultra port's `auto_brightness` endpoint.

## Installed pieces

- `libssc` 0.4.4-t6302
- `hexagonrpcd` 0.4.0-t6302
- `iio-sensor-proxy` 3.9-t6302
- `/usr/local/sbin/t630-sensors-start`
- `/usr/local/libexec/t630-session-manager`
- `/etc/udev/rules.d/61-t630-sensors.rules`
- `/etc/polkit-1/rules.d/49-t630-sensorproxy.rules`

The tablet's custom desktop startup launches the sensor stack after audio has
finished attaching to the shared ADSP. A short accelerometer probe primes SSC
discovery before the desktop proxy starts.

The custom login session now provides the small SessionManager interface that
GNOME's power daemon expects, starts that daemon after
`/run/t630-sensors-ready`, and grants the dedicated `tablet` account permission
to claim the read-only SensorProxy streams. Automatic system suspend remains
disabled; the existing guarded Power-button suspend path is unchanged.

## Live evidence

- Accelerometer: roughly -0.22, -0.40, 9.79 m/s² while lying flat
- Ambient light: 8–9 lux in the test room
- Proximity: FAR
- Magnetometer: changing three-axis readings around 45 µT
- Compass: stable 275–278° heading
- Idle proxy sample: zero user CPU ticks over five seconds
- Automatic brightness: GNOME reacted to 8–9 lux and selected roughly 78–80%
  brightness without oscillation

Audio, Bluetooth, battery reporting and the GNOME session remained healthy
during the live sensor tests.

## Clean-boot evidence

Boot `03e0d0bc-2443-4226-9823-81db41c213e7` automatically restored GNOME,
Wi-Fi access, the speaker sink at 30%, the Bluetooth controller and BlueZ,
`hexagonrpcd`, and `iio-sensor-proxy`. SensorProxy reported accelerometer,
ambient-light and proximity support. The session bridge reported active, the
GNOME power daemon claimed the light sensor without a manual monitor, and the
kernel logged successful ADSP startup with no sensor timeout or crash.
